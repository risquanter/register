# ADR-014: Simulation Result Caching and Render-Time Curve Generation

**Status:** Accepted  
**Date:** 2026-07-18  
**Tags:** caching, content-addressing, LEC, simulation, performance

---

## Context

- Monte Carlo simulation of a leaf is cheap per node but not free, so repeating
  it for unchanged inputs is waste that grows with tree size and request rate.
- A cache keyed by a mutable node identifier needs an invalidation protocol, and
  every such protocol has a window in which a stale entry can still be served.
- Exact `P(Loss >= x)` at an arbitrary loss tick is computable from trial
  outcomes and not from a curve already rendered at other ticks.
- Several curves drawn together must share one tick domain, and that domain
  depends on which nodes are displayed together — a fact unknown when any one
  node's result is computed.
- A portfolio's outcomes are the combine of its children's outcomes (ADR-009),
  so storing them duplicates data that is already derivable in one fold.
- Simulated figures depend on the workspace's `seedEntityId`, which appears in
  no leaf's own fields.

---

## Decision

### 1. The cache stores trial outcomes, never rendered curves

The value is `LeafSimResult` — the `TrialOutcomes` monoid carrier plus the
content-only `NodeProvenance` record. Curves are produced from it on demand, so
any tick domain is available at any time and no interpolation is involved.

```scala
final case class LeafSimResult(
  outcomes: TrialOutcomes,      // nTrials + sparse Map[TrialId, Loss]
  provenance: NodeProvenance    // carries no node identity
)
```

### 2. The key is a content hash, and there is no invalidation

`ContentHashIndex` derives the key from the leaf's simulation-relevant
projection (`LeafSimContent`, ADR-032). The key is recomputed on every read, so
an edited leaf hashes to a different key and misses. Staleness is not prevented
by a protocol; it is unrepresentable.

```scala
trait ContentCache:
  def get(key: ContentHash): UIO[Option[LeafSimResult]]
  def put(key: ContentHash, value: LeafSimResult): UIO[Unit]
  def stats: UIO[CacheStats]
```

Entries whose key is no longer produced are unreachable orphans. `EvictionStrategy`
reclaims them; it is a memory-management policy and carries no correctness duty.

### 3. Leaf entries only — portfolios re-aggregate on read

A portfolio result is the fold of its children's results through
`TrialOutcomes.combine`. The fold is cheaper than the storage it would replace,
and caching it would create a second representation of the same figures.

### 4. One cache per workspace, holding identity-free values

`ContentCacheRegistry.forWorkspace(seedEntityId)` resolves the owning workspace's instance.
Because `seedEntityId` determines figures but is not part of any leaf's content,
separate instances are what keep two workspaces' entries apart; a shared cache
keyed on leaf content alone would serve one workspace's figures to another.

Within an instance the value carries no `NodeId`, so two leaves with identical
simulation inputs share one entry. The resolver attaches the requested node's id
when it builds the result.

### 5. The tick domain is computed at render time across all requested curves

`LECGenerator.generateCurvePointsMulti` takes the combined loss range over every
result in the request, generates one shared tick vector, and evaluates each
result's exceedance at those ticks.

```scala
val combinedMin = nonEmpty.values.map(_.minLoss).min
val combinedMax = nonEmpty.values.map(clippedMaxLoss).max
val sharedTicks = (0L +: getTicks(combinedMin, combinedMax, nEntries)).distinct
results.map((nodeId, r) => nodeId -> sharedTicks.map(t => (t, exceedanceAt(r, t))))
```

## Code Smells

### ❌ Caching rendered curve points

```scala
// BAD: the tick domain is a property of the request, not of the node
cache.put(key, generateCurvePoints(result, nTicks = 100))

// GOOD: cache outcomes; render against the request's shared ticks
cache.put(key, LeafSimResult(outcomes, provenance))
LECGenerator.generateCurvePointsMulti(results, nTicks)
```

### ❌ Adding an invalidation operation

```scala
// BAD: reintroduces the stale-entry window content addressing removes
def invalidate(nodeId: NodeId): UIO[List[NodeId]]

// GOOD: edit the leaf; its content hash changes and the read misses
contentHashIndex.hashOf(leaf)   // different key, no eviction needed
```

### ❌ Caching a portfolio result

```scala
// BAD: a second copy of figures the children already hold
cache.put(portfolioKey, aggregated)

// GOOD: fold the children on read
RiskResultGroup.create(portfolio.id, childResults*)
```

### ❌ One cache shared across workspaces

```scala
// BAD: identical leaf content in two workspaces collides, and the entry
//      carries figures simulated under the other workspace's entity seed
val global: ContentCache = ...

// GOOD: resolve the owning workspace's instance
caches.forWorkspace(ws.seedEntityId)
```

### ❌ Putting node identity in the cached value

```scala
// BAD: two content-identical leaves can no longer share an entry
final case class LeafSimResult(nodeId: NodeId, outcomes: TrialOutcomes, ...)

// GOOD: identity is attached by the resolver at the edge
RiskResult(requestedNodeId, cached.outcomes, List(cached.provenance))
```

## Implementation

| Location | Pattern |
|----------|---------|
| `services/cache/ContentCache.scala` | `ContentHash → LeafSimResult` store, `CacheStats` |
| `services/cache/LeafSimResult.scala` | Identity-free cached value |
| `services/cache/ContentHashIndex.scala` | Key derivation from the leaf projection |
| `services/cache/ContentCacheRegistry.scala` | Per-workspace instance resolution |
| `services/cache/EvictionStrategy.scala` | Orphan reclamation; no correctness role |
| `services/cache/CachedResultResolverLive.scala` | Cache-aside reads, portfolio fold, identity attachment |
| `simulation/LECGenerator.scala` | `generateCurvePointsMulti` shared tick domain |
