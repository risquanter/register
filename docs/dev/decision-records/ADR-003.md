# ADR-003: Provenance and Reproducibility

**Status:** Accepted  
**Date:** 2026-09-25  
**Tags:** provenance, reproducibility, hdr, monte-carlo, determinism

---

## Context

- Monte Carlo results must be reproducible from stored data alone, both for audit and so that two scenarios can be compared difference by difference.
- Choosing a random stream by hashing a name or an application identifier makes the figures depend on values that exist for unrelated reasons: renaming a node or rebuilding the same model changes the numbers.
- HDR identifier axes are bounded at eight decimal digits. A value at or above 10⁸ breaks the modulus precision under which the generator's statistical validation was established.
- One risk's occurrence sampling and loss sampling must draw from streams that cannot correlate with each other, or with any other leaf's streams.
- An audit record is only useful if it is self-sufficient: the stream coordinates and the full distribution parameters must both be stored, serializable, and retrievable without loading curve data.

---

## Decision

### 1. Four-Layer HDR Seed Hierarchy

Every draw is a pure function of the trial number and four seed coordinates:

```scala
HDR.generate(trial, entityId, varId, seed3, seed4)

// SeedDerivation.streams — the only place stream coordinates are computed
entityId        = workspace.seedEntityId               // layer 2: workspace isolation
occurrenceVarId = 2 * leaf.seedVarId                   // layer 3: even stream
lossVarId       = 2 * leaf.seedVarId + 1               //          odd stream
seed3, seed4    = config.defaultSeed3, defaultSeed4    // layer 4: global knobs
```

- The trial number separates draws within one run.
- `seedEntityId` gives each workspace independent streams.
- The parity split makes a leaf's occurrence and loss streams disjoint, and disjoint from every other leaf's, because `seedVarId` values are distinct within a tree.
- The two global seeds shift every stream at once, which is how the whole simulation outcome changes from one parameter.

### 2. Seed Identity Is Assigned Data, Stored on the Node

Stochastic identity is separate from application identity. A node's ULID answers "which node"; its seed ID answers "which random stream". Neither is derived from the other, and neither is derived from a name.

```scala
// Iron-refined, range-validated at the codec boundary (ADR-001)
type SeedEntityIdLong = Long :| (GreaterEqual[1L] & Less[100000000L])  // 0 is HDR's shared default
type SeedVarIdLong    = Long :| (GreaterEqual[1L] & Less[50000000L])   // 2k+1 stays below 10^8

// Workspace carries seedEntityId, RiskLeaf carries seedVarId, RiskPortfolio carries neither:
// a portfolio's trials are sums of its children and draw nothing of their own.
```

- A create request may provide a `seedVarId`. When it does not, the server assigns one at the boundary, taking the unprovided leaves in sorted-name order and numbering them consecutively from `RiskTree.seedVarHighWater + 1`.
- Assignment reads the high-water mark, never the highest ID in use, so a deleted leaf's ID is never re-issued to a different risk.
- `seedVarId` is distinct per tree rather than per deployment: scenario branches share IDs, so unedited leaves draw identically and every difference between two branches' curves is attributable to the edit.
- `seedEntityId` is unique per deployment and comes from a store sequence.
- A seed ID is immutable once assigned, and an update request does not accept one for an existing node. `seedVarId` is part of a node's content hash and the name is not, so renaming changes no figure and invalidates no cache entry (ADR-014, ADR-032).

### 3. Service-Wide Simulation Parameters

Simulation parameters come from `SimulationConfig`, never from a tree or a request:

```scala
// application.conf, overridable per environment
defaultNTrials           // REGISTER_DEFAULT_NTRIALS
defaultTrialParallelism  // REGISTER_TRIAL_PARALLELISM
defaultSeed3             // REGISTER_SEED3
defaultSeed4             // REGISTER_SEED4

// CachedResultResolverLive reads them once at construction.
```

**Why service-wide:**
- Reproducibility is consistent across every simulation the deployment runs
- Cache keys carry no per-request variation
- `RiskResult.nTrials` keeps aggregation from combining results drawn at different trial counts

### 4. Provenance Is Captured Unconditionally, on Leaves Only

Provenance is written to every `RiskResult` at simulation time, so a cached result always carries its complete audit record and no later path has to populate one. The `provenances: List[NodeProvenance] = Nil` default exists for domain-object construction — test fixtures and intermediate aggregation states — and is always `List(provenance)` by the time a result reaches the cache.

A portfolio stores no provenance of its own. Its records are read by walking its children and pairing each child's `nodeId` with that child's records, giving the union of all leaf provenances in the subtree, in child order. Provenance is served by a dedicated audit endpoint, never embedded in curve or exceedance responses.

```scala
case class NodeProvenance(   // content-only: carries no node identity
  entityId: Long,
  occurrenceVarId: Long,
  lossVarId: Long,
  globalSeed3: Long,
  globalSeed4: Long,
  distributionType: String,
  distributionParams: DistributionParams,
  timestamp: Instant,
  metalogDistributionVersion: String
)

// simulateLeaf (CachedResultResolverLive) — the content-addressed cache stores the
// identity-free pair; the resolver attaches the requested node's ID at the edge.
cache.put(contentHash, LeafSimResult(outcomes, provenance))
RiskResult.fromTrialOutcomes(leaf.id, outcomes, List(provenance))

// aggregation — attribution is structural: pair each child's nodeId with its records
// one level above any flattening. The sealed supertype exposes no flat list.
group.children.collect { case r: RiskResult => r.nodeId -> r.provenances }
```

- Provenance travels with the cached leaf result, so reproduction needs no second lookup
- Aggregates thread nothing: the derivation is automatic and order-stable
- Each leaf has independent streams, so a record per leaf is enough to reproduce any subtree

### 5. Distribution Parameter Storage

A record stores every parameter needed to rebuild the exact distribution it was drawn from:

```scala
sealed trait DistributionParams

case class MetalogParams(
  percentiles: Array[Double],   // [0.1, 0.5, 0.9]
  quantiles: Array[Double],     // [1000, 5000, 20000]
  terms: Int,                   // 3 or 9 terms
  lowerBound: Option[Double],   // semi-bounded
  upperBound: Option[Double]
) extends DistributionParams

case class LognormalParams(
  minLoss: Long,                // P05, the 90% interval's lower bound
  maxLoss: Long,                // P95, the 90% interval's upper bound
  confidenceInterval: Double = 0.90
) extends DistributionParams
```

## Code Smells

### ❌ Global Seed State

```scala
// BAD: mutable global seed
object RandomState {
  var globalSeed: Long = 0L
  def nextRandom(): Double = { /* mutate state */ }
}

// GOOD: pure HDR function
def sample(trial: Int, entityId: Long, varId: Long, seed3: Long, seed4: Long): Double =
  HDR.generate(trial, entityId, varId, seed3, seed4)
```

### ❌ Seed Derived from a Name or an Application Identifier

```scala
// BAD: the stream is a function of values that change for unrelated reasons
val entitySeed = leaf.id.value.hashCode       // ULIDs are time-ordered: rebuild, new figures
val varSeed    = leaf.name.hashCode + 1000L   // rename, new figures
// Out of range as well: hashCode spans ±2^31, 21× the 10^8 ID budget.

// GOOD: assigned, stored, range-refined identity through the single derivation site
val streams = SeedDerivation.streams(workspace.seedEntityId, leaf.seedVarId, seed3, seed4)
```

### ❌ Missing Variable Isolation

```scala
// BAD: occurrence and loss share one varId
val occurred = HDR.generate(trial, entityId, varId = entityId, seed3, seed4) < prob
val loss     = HDR.generate(trial, entityId, varId = entityId, seed3, seed4) * scale
// Occurrence and loss are then correlated.

// GOOD: the parity split gives two disjoint streams
val streams  = SeedDerivation.streams(workspace.seedEntityId, leaf.seedVarId, seed3, seed4)
val occurred = HDR.generate(trial, streams.entityId, streams.occurrenceVarId, seed3, seed4) < prob
val loss     = HDR.generate(trial, streams.entityId, streams.lossVarId, seed3, seed4) * scale
```

### ❌ Mandatory Provenance in Domain Objects

```scala
// BAD: provenance required at construction — blocks test data and intermediate aggregation
case class RiskResult(
  outcomes: Map[TrialId, Loss],
  provenance: NodeProvenance  // cannot construct without running a simulation
)

// GOOD: Nil default for construction; the simulation path always supplies the list
case class RiskResult(
  outcomes: Map[TrialId, Loss],
  provenances: List[NodeProvenance] = Nil
)
```

### ❌ A Provenance Record That Cannot Rebuild Its Distribution

```scala
// BAD: the fit cannot be recreated from what was stored
case class MetalogParams(
  terms: Int  // percentiles and quantiles missing
)

// GOOD: every input the fit consumed is in the record (Decision 5)
MetalogParams(percentiles, quantiles, terms, lowerBound, upperBound)
```

## Reproduction

Rebuild each leaf's distribution from its record's `distributionParams`, construct a `RiskSampler` from the same record's `entityId`, `occurrenceVarId`, `lossVarId`, `globalSeed3` and `globalSeed4`, and run at the trial count in `RiskResult.nTrials`. Results match the original to floating-point precision.

| Case | Reproduces |
|---|---|
| Re-simulating a stored tree | Yes — seed IDs are stored data |
| Deleting and rebuilding the same model in the same workspace, no seed IDs provided | Yes — sorted-name assignment is determined by content |
| The same model in a second workspace | No, by design — a different `seedEntityId` isolates workspaces |
| The same model in a second workspace or deployment with seed IDs provided | Yes — export carries the seed IDs |
| A scenario branch against its parent, for the nodes neither edited | Yes — the branch shares seed IDs |
| Every other leaf after one leaf's parameters change | Yes — their draws are byte-identical |
