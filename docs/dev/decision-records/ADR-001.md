# ADR-001: Validation Strategy with Iron Types and Smart Constructors

**Status:** Accepted  
**Date:** 2026-01-09  
**Tags:** validation, iron, zio-prelude, ddd

---

## Context

External input (HTTP, JSON) is untrusted. Domain objects must be correct by
construction: validation happens once, at the domain boundary, and internal code
trusts the validated types. Iron refined types encode field constraints in the
type; ZIO Prelude `Validation` accumulates independent errors instead of failing
on the first.

---

## Decision

### 1. Smart constructors build every domain object (parse, don't validate)

A domain object is constructed only through a `create()` returning
`Validation[ValidationError, T]`, layering per-field Iron refinement then
cross-field business rules. JSON decoders call the smart constructor, so no raw
object bypasses validation.

```scala
object RiskLeaf:
  def create(id: String, name: String, probability: Double /* raw inputs */)
      : Validation[ValidationError, RiskLeaf] =
    // Layer 1 — per-field Iron refinement
    val idV   = toValidation(ValidationUtil.refineId(id, "id"))
    val nameV = toValidation(ValidationUtil.refineName(name, "name"))
    val probV = toValidation(ValidationUtil.refineProbability(probability, "probability"))
    // Layer 2 — cross-field business rules (e.g. minLoss < maxLoss)
    Validation.validateWith(idV, nameV, probV)(RiskLeaf(_, _, _))

// JSON parsing routes through the smart constructor
given JsonDecoder[RiskLeaf] = RiskLeafRaw.rawCodec.decoder.mapOrFail: raw =>
  RiskLeaf.create(raw.id, raw.name, raw.probability).toEither.left.map(_.mkString("; "))
```

Accumulate independent errors with `Validation.validateWith` (ZIO Prelude), never
`Either`/`.flatMap` — the latter reports only the first failure.

### 2. Validate once, at the earliest boundary

Tapir codecs refine query and path parameters to Iron types during URL parsing;
invalid input returns 400 Bad Request before any controller runs. Controllers and
services are "dumb": they receive already-validated Iron types and perform no
validation.

```scala
// Query/path params — codec validates, endpoint speaks Iron/domain types
given Codec[String, PositiveInt, CodecFormat.TextPlain] =
  Codec.int.mapDecode(raw => ValidationUtil.refinePositiveInt(raw, "nTrials") match
    case Right(pi)  => DecodeResult.Value(pi)
    case Left(errs) => DecodeResult.Error(raw.toString, IllegalArgumentException(errs.map(_.message).mkString("; "))))(pi => pi: Int)
.in(query[Option[PositiveInt]]("nTrials"))
.in("risk-trees" / path[TreeId]("treeId"))   // TreeId codec refines at the boundary
```

A JSON body that carries a bare Iron type (not wrapped in a DTO with a smart
constructor) needs **two** givens: a `JsonCodec[IronType]` for serialization and an
explicit `Schema[IronType]` for OpenAPI. Path/query params derive their `Schema`
from the `Codec`; JSON bodies do not, so the `Schema` must be supplied.

```scala
.in(jsonBody[List[SafeId.SafeId]])           // Iron type directly in the body
given Schema[SafeId.SafeId] = Schema.string  // required — not auto-derived for bodies
```

### 3. Iron types propagate through every layer

Service and repository signatures, storage keys, and all internal structures that
reference domain entities (caches, indexes, event queues, map keys) use the same
domain Iron type as the model — never a raw `String`. This keeps one source of
truth for an ID type and prevents accidental String/ID mixing in lookups and
comparisons.

```scala
trait RiskTreeService:
  def getById(id: TreeId): Task[Option[RiskTree]]        // domain type, not String
final case class TreeIndex(nodes: Map[NodeId, RiskNode], parents: Map[NodeId, NodeId])
private val db = TrieMap[TreeId, RiskTree]()             // storage keyed by domain type
```

### 4. Choose the URL constraint by trust boundary

Internal/service URLs (docker, k8s, localhost, IPv4/IPv6, optional port/path) use
the relaxed `UrlConstraint` (`SafeUrl` — http/https, regex-based to allow
non-public hostnames). A stricter `PublicUrl` type (Iron `ValidURL` or a tighter
regex) is introduced only when a real user-supplied/public-URL use case exists, so
internal endpoints are not over-constrained.

> HTTPS-only credential-bearing endpoints and outbound-header token constraints
> (`SecureUrlConstraint`, `PrintableAscii`, `ExternalTokenStr`) are an
> output-boundary concern — see the appendix, "External-System Output Boundary
> Constraints".

## Code Smells

### ❌ Validation or parsing below the boundary

```scala
// BAD — controller parses/validates; service re-validates raw primitives
.in(path[String]("id"))
val getById = ep.serverLogicSuccess(idStr => ZIO.attempt(idStr.toLong).flatMap(svc.getById))
def computeLEC(nTrials: Int, depth: Int) = /* refine inside the service */

// GOOD — codec refines at the boundary; controller wires; service trusts Iron types
.in(path[TreeId]("treeId"))
val getById = ep.serverLogicSuccess(svc.getById)             // id already a TreeId
def computeLEC(nTrials: PositiveInt, depth: NonNegativeInt)  // no validation
```

Non-valid input (e.g. `/risk-trees/abc`) must return 400 from Tapir, not 500 from a
controller. No validation happens in service methods.

### ❌ Option-based smart constructors

```scala
// BAD — no error detail, no accumulation
def create(name: String): Option[SafeName] = Option.when(name.nonEmpty && name.length <= 50)(SafeName(name))
// GOOD
def create(name: String): Validation[ValidationError, SafeName] = toValidation(ValidationUtil.refineName(name, "name"))
```

### ❌ Fail-fast `Either` for independent fields

```scala
// BAD — user sees only the first error
for { i <- refineId(id); n <- refineName(name) } yield build(i, n)
// GOOD — all errors surface
Validation.validateWith(toValidation(refineId(id)), toValidation(refineName(name)))(build)
```

### ❌ Bypassing with `.refineUnsafe` in production

```scala
val nTrials = input.refineUnsafe[Greater[0]]        // BAD — runtime crash if invalid
ValidationUtil.refinePositiveInt(input, "nTrials")  // GOOD — validation at the boundary
```

## Implementation

| Location | Pattern |
|---|---|
| `RiskLeaf.create()`, `RiskPortfolio.create()` | Smart constructor returning `Validation` |
| `JsonDecoder[RiskLeaf]` | Calls `create()` during parsing |
| `IronTapirCodecs` | Tapir codecs for query/path params; explicit `Schema` for JSON-body Iron types |
| `RiskTreeEndpoints` | Iron/domain types (`TreeId`, `NodeId`) end-to-end |
| `RiskTreeController` | Wires only — no validation or parsing |
| `RiskTreeService`, `RiskTreeRepository` | Iron/domain types in signatures and storage keys |
| `ValidationUtil` | Iron refinement helpers |
