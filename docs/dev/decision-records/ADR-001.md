# ADR-001: Validation Strategy with Iron Types and Smart Constructors

**Status:** Accepted  
**Date:** 2026-01-09  
**Tags:** validation, iron, zio-prelude, ddd

---

## Context

External input (HTTP, JSON) is untrusted. Domain objects must be correct by
construction: validation happens once, at the domain boundary, and internal code
trusts the validated types. Iron refined types encode field constraints in the
type; ZIO Prelude `Validation` accumulates independent errors instead of failing
on the first.

HTTP is the instance this record is written for, and it is the most exercised
one, but it is an instance. The general rule — that validation belongs wherever
a value enters process memory from outside, and that a store this service wrote
to is outside — is
[ADR-039](ADR-039-trust-boundary-ingress-validation.md). The two divide
cleanly: ADR-039 says where the boundary is, this record says what happens when
a value crosses it and that nothing inside validates again.

---

## Decision

### 1. Smart constructors build every domain object (parse, don't validate)

A domain object is constructed only through a `create()` returning
`Validation[ValidationError, T]`, layering per-field Iron refinement then
cross-field business rules. JSON decoders call the smart constructor, so no raw
object bypasses validation.

```scala
object RiskLeaf:
  def create(id: String, name: String, probability: Double /* raw inputs */, subject: ErrorSubject)
      : Validation[ValidationError, RiskLeaf] =
    // Layer 1 — per-field Iron refinement, each refusal located at its field
    val idV   = toValidation(ValidationUtil.refineId(id, ErrorLocation.Field(subject, FieldName.Id)))
    val nameV = toValidation(ValidationUtil.refineName(name, ErrorLocation.Field(subject, FieldName.Name)))
    val probV = toValidation(ValidationUtil.refineProbability(probability, ErrorLocation.Field(subject, FieldName.Probability)))
    // Layer 2 — cross-field business rules (e.g. minLoss < maxLoss)
    Validation.validateWith(idV, nameV, probV)(RiskLeaf(_, _, _))

// JSON parsing routes through the smart constructor
given JsonDecoder[RiskLeaf] = RiskLeafRaw.rawCodec.decoder.mapOrFail: raw =>
  RiskLeaf.create(raw.id, raw.name, raw.probability, ErrorSubject.Request).toEither.left.map(_.mkString("; "))
```

Accumulate independent errors with `Validation.validateWith` (ZIO Prelude), never
`Either`/`.flatMap` — the latter reports only the first failure. A collection
above its ceiling is the one exception: `resolve` refuses the submission by its
count alone, before any entry is refined, so the work and the refusal are bounded
by the ceilings and not by the request body (ADR-017 §6).

### 2. Each rule is checked once, at the first point that holds what it reads

A rule is placed by the information it reads. In domain-driven design (DDD)
terms, a client request is a **command**, and the rules a command must satisfy
are of three kinds. Each kind has one home.

| What the rule reads | DDD name | Where it is checked | Examples |
|---|---|---|---|
| One value, alone | Value-object invariant | The codec: a Tapir codec for a path, query or header value, a JSON decoder for a body | `TreeId` in the path, `SafeName`, `Probability`, `TargetingPredicate` |
| The aggregate being built, alone | Aggregate invariant, enforced by the aggregate's factory | The aggregate's smart constructor | `RiskTree.fromNodes`: one root, unique names, no cycle, the node and mitigation bounds, which for a submitted tree are also checked first at the service's entry step and in `resolve` |
| The command against state the server holds | Command precondition | The application service's entry step, after it loads the aggregate, through the command's own pure `resolve` function, at `TrustZone.Client` | An update entry names a stored leaf. An absolute mitigation's anchor names an existing leaf. A new node's identifier is minted by the server |

An *aggregate* is a cluster of objects that changes as one unit and guards one
set of invariants. A risk tree with its nodes and mitigations is one. An
*application service* is the operation that carries out one command: it loads
the aggregate, applies the command and stores the result. In this codebase that
is a method of `RiskTreeServiceLive` or one of its siblings.

A rule checked later than the point that first holds its information is a
defect, with one exception. A command refined as a whole checks every kind of
rule in one `Validation`, inside its `resolve` function, so that every refusal
is reported together and each is located at its entry. The tree create and
update are such commands. Their value-object invariants are therefore checked at
the service's entry step and not in the decoder. The reason is the decode
channel. A zio-json decoder can fail only with a string, and
`WireDecodeFailureHandler` answers any refused body with one `Unreadable`
problem at `ErrorLocation.Whole`. Decoding those values would turn a list of
located refusals into one unlocated one.

The exception has one limit. A submission whose node count or mitigation count
is above its tree ceiling is refused by that count alone, before any work its
size drives. The service checks the counts before it mints identifiers or writes
a record, and `resolve` checks them again first, before any entry is refined. A
result-stage pipeline above its step ceiling is likewise refused by its step
count alone, before any step is refined. Its other refusals are not reported, because
refining every entry of an oversized submission would make the work and the
refusal grow with the request body rather than with the ceilings. The counts
are held by the command itself, so the request is the first point that holds
them.

**Relation to ADR-017.** ADR-017's tree request types carry raw fields because of
this exception, and ADR-017 §3 says so. Any collection the tree request gains is
refined by the same `resolve` and reported in the same `Validation`.

Once the entry step has returned, nothing validates again. The domain services,
the simulation and the signature side of a repository receive refined types and
check none of them.

Tapir codecs refine query and path parameters to Iron types during URL parsing,
and invalid input returns 400 Bad Request before any controller runs.
Controllers check nothing.

```scala
// Query/path params — codec validates, endpoint speaks Iron/domain types
given Codec[String, PositiveInt, CodecFormat.TextPlain] =
  Codec.int.mapDecode[PositiveInt](raw =>
    ValidationUtil.refinePositiveInt(raw, ErrorLocation.Whole).fold(
      refused,                // DecodeResult.InvalidValue carrying each error's FieldProblem
      DecodeResult.Value(_)
    )
  )(identity)
.in(query[Option[PositiveInt]]("nTrials"))
.in("risk-trees" / path[TreeId]("treeId"))   // TreeId codec refines at the boundary
```

A JSON body that carries a bare Iron type (not wrapped in a DTO with a smart
constructor) needs **two** givens: a `JsonCodec[IronType]` for serialization and an
explicit `Schema[IronType]` for OpenAPI. Path/query params derive their `Schema`
from the `Codec`; JSON bodies do not, so the `Schema` must be supplied.

```scala
.in(jsonBody[List[SafeId.SafeId]])           // Iron type directly in the body
given Schema[SafeId.SafeId] = Schema.string  // required — not auto-derived for bodies
```

### 3. Iron types propagate through every layer

Service and repository signatures, storage keys, and all internal structures that
reference domain entities (caches, indexes, event queues, map keys) use the same
domain Iron type as the model — never a raw `String`. This keeps one source of
truth for an ID type and prevents accidental String/ID mixing in lookups and
comparisons.

```scala
trait RiskTreeService:
  def getById(id: TreeId): Task[Option[RiskTree]]        // domain type, not String
final case class TreeIndex(nodes: Map[NodeId, RiskNode], parents: Map[NodeId, NodeId])
private val db = TrieMap[TreeId, RiskTree]()             // storage keyed by domain type
```

### 4. Choose the URL constraint by trust boundary

Internal/service URLs (docker, k8s, localhost, IPv4/IPv6, optional port/path) use
the relaxed `UrlConstraint` (`SafeUrl` — http/https, regex-based to allow
non-public hostnames). A stricter `PublicUrl` type (Iron `ValidURL` or a tighter
regex) is introduced only when a real user-supplied/public-URL use case exists, so
internal endpoints are not over-constrained.

> HTTPS-only credential-bearing endpoints and outbound-header token constraints
> (`SecureUrlConstraint`, `PrintableAscii`, `ExternalTokenStr`) are an
> output-boundary concern — see the appendix, "External-System Output Boundary
> Constraints".

### 5. Aggregate constructors are private — the smart constructor is the only gate

A domain aggregate is declared `final case class X private (...)`, with all
construction routed through a smart constructor (`create` / `fromNodes`)
returning `Validation[ValidationError, X]`. Scala 3 makes the compiler-generated
`.copy` private when the primary constructor is private (E173), so once the
constructor is private there is no `apply` or `.copy` path that skips
validation — the smart constructor is the sole gate for every construction site
(builders, merges, store-loads, tests). This generalizes the `PortfolioLosses`
private constructor (ADR-034) to every aggregate.

An aggregate built only from values the server computed has no refusal to report,
because no user input reaches it. Its constructor enforces the invariant with
`require` (ADR-033 §5). `TrialOutcomes` is this case.

Reference aggregates: `RiskLeaf`, `RiskPortfolio`, `Mitigation`,
`PortfolioLosses`, `RiskTree`, `TreeIndex`.

```scala
final case class RiskTree private (             // primary ctor private → .copy private too
  id: TreeId, name: SafeName, nodes: Seq[RiskNode], rootId: NodeId, index: TreeIndex /* … */
)
object RiskTree:
  def fromNodes(id: TreeId, name: SafeName, nodes: Seq[RiskNode], rootId: NodeId /* … */)
      : Validation[ValidationError, RiskTree] = ???   // the only way to build one
```

## Code Smells

### ❌ Validation or parsing below the boundary

```scala
// BAD — controller parses/validates; service re-validates raw primitives
.in(path[String]("id"))
val getById = ep.serverLogicSuccess(idStr => ZIO.attempt(idStr.toLong).flatMap(svc.getById))
def computeLEC(nTrials: Int, depth: Int) = /* refine inside the service */

// GOOD — codec refines at the boundary; controller wires; service trusts Iron types
.in(path[TreeId]("treeId"))
val getById = ep.serverLogicSuccess(svc.getById)             // id already a TreeId
def computeLEC(nTrials: PositiveInt, depth: NonNegativeInt)  // no validation
```

Non-valid input (e.g. `/risk-trees/abc`) must return 400 from Tapir, not 500 from a
controller. A service checks a command's preconditions at its entry step and
checks nothing after it (§2).

### ❌ Option-based smart constructors

```scala
// BAD — no error detail, no accumulation
def create(name: String): Option[SafeName] = Option.when(name.nonEmpty && name.length <= 50)(SafeName(name))
// GOOD
def create(name: String): Validation[ValidationError, SafeName] = toValidation(ValidationUtil.refineName(name, ErrorLocation.requestField(FieldName.Name)))
```

### ❌ Fail-fast `Either` for independent fields

```scala
// BAD — user sees only the first error
for { i <- refineId(id, idAt); n <- refineName(name, nameAt) } yield build(i, n)
// GOOD — all errors surface
Validation.validateWith(toValidation(refineId(id, idAt)), toValidation(refineName(name, nameAt)))(build)
```

### ❌ Bypassing with `.refineUnsafe` in production

```scala
val nTrials = input.refineUnsafe[Greater[0]]        // BAD — runtime crash if invalid
ValidationUtil.refinePositiveInt(input, ErrorLocation.Whole)  // GOOD — validation at the boundary
```

### ❌ Public aggregate constructor (`apply`/`.copy` bypass every invariant)

```scala
// BAD — public primary constructor; `apply` and `.copy` skip fromNodes' invariants
final case class RiskTree(id: TreeId, name: SafeName, nodes: Seq[RiskNode], rootId: NodeId, index: TreeIndex)
val forged = valid.copy(nodes = tooMany)   // no node-count / name-uniqueness / structure check

// GOOD — private primary constructor; fromNodes is the sole gate
final case class RiskTree private (id: TreeId, name: SafeName, nodes: Seq[RiskNode], rootId: NodeId, index: TreeIndex)
RiskTree.fromNodes(id, name, nodes, rootId)   // returns Validation, runs every invariant
```

## Implementation

| Location | Pattern |
|---|---|
| `RiskLeaf.create()`, `RiskPortfolio.create()` | Smart constructor returning `Validation` |
| `RiskTree`, `TreeIndex`, `PortfolioLosses` | Aggregate with `private` primary constructor — smart constructor (`fromNodes`/`create`) is the sole gate |
| `JsonDecoder[RiskLeaf]` | Calls `create()` during parsing |
| `IronTapirCodecs` | Tapir codecs for query/path params; explicit `Schema` for JSON-body Iron types |
| `WorkspaceTreeEndpoints`, `WorkspaceAnalysisEndpoints` | Iron/domain types (`TreeId`, `NodeId`) end-to-end |
| `WorkspaceTreeController`, `WorkspaceAnalysisController` | Wires only — no validation or parsing |
| `RiskTreeDefinitionRequest.resolve`, `RiskTreeUpdateRequest.resolve` | A command refined as a whole at the service's entry step: every refusal together, each located at its entry (§2) |
| `RiskTreeService`, `RiskTreeRepository` | Iron/domain types in signatures and storage keys |
| `ValidationUtil` | Iron refinement helpers |
