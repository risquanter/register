# ADR-009: Compositional Risk Aggregation via the TrialOutcomes Monoid

**Status:** Accepted  
**Date:** 2026-07-17  
**Tags:** architecture, domain-model, zio-prelude, aggregation, monoid

---

## Context

- Aggregate nodes must produce loss distributions for LEC visualisation even though only leaf nodes carry distribution parameters — consumers need one read interface for both kinds
- Trial-aligned outcomes combine by pointwise summation, but a combine is only a lawful monoid on data that excludes node identity: a parent's node ID has no principled derivation from its children's IDs, so any instance on an identity-carrying type must invent one
- Parallel and order-independent aggregation is safe only when licensed by stated, tested algebraic laws — not by convention
- The identity element's `nTrials` derives from configuration, so an `Identity` instance must be scoped to `SimulationConfig` to avoid trial-count drift
- Every node's LEC curve must be traceable to the contributing leaves (ADR-003); provenance belongs to the node that was simulated, never to the aggregate

---

## Decision

### 1. The algebra lives on `TrialOutcomes`, not on a result type

`LossDistribution` is the product `NodeId × TrialOutcomes`: the node ID is a label supplied by tree context; only the trial data participates in combination.

```scala
case class TrialOutcomes(nTrials: Int, outcomes: Map[TrialId, Loss])

object TrialOutcomes {
  def empty(using cfg: SimulationConfig): TrialOutcomes           // identity element
  def combine(a: TrialOutcomes, b: TrialOutcomes): TrialOutcomes  // outer-join pointwise sum,
                                                                  // same-nTrials alignment enforced
  given commutative: Commutative[TrialOutcomes]                   // extends Associative — one instance, both laws
  given identity(using SimulationConfig): Identity[TrialOutcomes] // config-scoped, opt-in
}
```

### 2. One read interface, one concrete value

Every consumer receives the same concrete type. Whether a node was simulated or aggregated is not encoded in its shape:

```scala
final case class LossDistribution private (
  nodeId: NodeId,
  trials: TrialOutcomes,                       // after this node's own mitigation layer
  source: TrialOutcomes,                       // the figures that layer was applied to
  applied: List[MitigationApplicationRecord],  // empty = no layer here
  provenance: Option[NodeProvenance]           // a simulated leaf has one; a portfolio none
) extends LECCurve
```

`LECGenerator`, the resolver, and the query knowledge base all take `LossDistribution`.

The leaf/aggregate distinction lives on an internal family that no consumer can name — `NodeLosses`, with `LeafLosses` and `PortfolioLosses` as its two cases, `private[cache]` beside the resolver. It is sealed in one file, so a third origin is still a compile error wherever it is matched.

### 3. Portfolio construction is a named constructor, not a monoid reduction

The parent ID comes from the tree; the outcomes come from the algebra:

```scala
// CachedResultResolverLive — portfolio branch
PortfolioLosses.create(portfolio.id, childResults)   // childResults: List[LossDistribution]
// internally: children's TrialOutcomes reduced with TrialOutcomes.combine
```

The factory derives the aggregate from the children it is given and offers no parameter through which a different total could arrive, so the trial count carried by the result is the children's own and never one read from configuration.

### 4. Laws license parallel child resolution

Associativity and commutativity make evaluation order irrelevant to the figures, so the resolver resolves portfolio children concurrently:

```scala
childResults <- ZIO.foreachPar(portfolio.childIds.toList)(resolveChild)
// foreachPar preserves list order → provenance order identical to sequential
```

### 5. Provenance is attributed by node, never merged into the aggregate

```scala
// A simulated leaf carries its own content-only record; a portfolio carries none.
// Each record is keyed by the node whose value holds it:
LossDistribution.leafProvenances(results)   // Map[NodeId, LossDistribution] => Map[NodeId, NodeProvenance]
```

A subtree's records are read by taking its leaf set from `TreeIndex` and resolving each
leaf under that leaf's own identifier. Nothing traverses a returned value, so a value's
size is bounded by its node rather than by the subtree beneath it. `NodeProvenance`
carries no node identity of its own, so a record can only be attributed through the node
whose value holds it.

## Code Smells

### ❌ Monoid instance on an identity-carrying type

```scala
// BAD: combine has no principled nodeId for the result — it must steal one
given Associative[LossDistribution] with
  def combine(a: => LossDistribution, b: => LossDistribution) = LossDistribution(a.nodeId, ...)

// GOOD: instance on the identity-free payload
given commutative: Commutative[TrialOutcomes]
```

### ❌ An aggregate assembled from figures rather than derived from children

```scala
// BAD: a total supplied by the caller, which nothing forces to equal the children
PortfolioLosses(portfolio.id, someTotal, childResults)

// GOOD: the factory derives the total from exactly the children it is given
PortfolioLosses.create(portfolio.id, childResults)
```

### ❌ Manual trial alignment

```scala
// BAD: hand-rolled per-trial summation at the call site
allTrials.map(t => t -> children.map(_.outcomes.getOrElse(t, 0L)).sum).toMap

// GOOD: the single combine implementation
children.map(_.trials).reduceOption(TrialOutcomes.combine)
```

### ❌ Unlicensed parallelism

```scala
// BAD: foreachPar over an aggregation with no stated associativity law
// GOOD: laws stated as zio-prelude instances, verified by property tests
//       (TrialOutcomesSpec), then foreachPar
```

## Implementation

| Component | Location | Purpose |
|-----------|----------|---------|
| `TrialOutcomes` + instances | `simulation/LossDistribution.scala` (server) | The lawful commutative monoid |
| `LossDistribution` | `simulation/LossDistribution.scala` (server) | The one concrete value every consumer receives |
| `NodeLosses` / `LeafLosses` / `PortfolioLosses` | `services/cache/NodeLosses.scala` (server) | Internal leaf / aggregate origins, `private[cache]` |
| `CachedResultResolverLive` | `services/cache/CachedResultResolverLive.scala` | Parallel child resolution, cache-aside (ADR-015) |
| `TrialOutcomesSpec` | `server` tests | Law suite exercised through the instances |
